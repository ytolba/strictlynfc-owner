# StrictlyVision native UI audit — 21 September 2026

Scope: combined member and owner app. Source review plus an iPhone 17 Pro simulator pass of Today, Scan, Gyms, Profile, and machine navigation. This is a UX/technical audit, not an App Store approval or a security review. Owner sign-in, a real NFC read, Android, iPad, large text, and VoiceOver/TalkBack still need device-level verification.

**Native-app verdict:** It reads as a functional native app on the tested iPhone, not a web page. The remaining off-platform feel comes mostly from a hand-built global tab bar/navigation model and card-heavy owner settings. This is not blocking daily use, but it is noticeable compared with standard iOS navigation and Android Material patterns.

## Changes completed in this pass

- A machine scan or visit no longer starts a workout. The first saved set starts it, and legacy empty sessions are cleared, preventing a zero-set timer from running for hours. The first set and its session are now saved together.
- Set logging gives immediate local confirmation, then updates its sync message. A successful save also gives a small haptic cue and a screen-reader announcement; failures use an error notice.
- NFC scanning has a restrained pulse while scanning. The generated workout appears with a brief fade. Both animations honor the system's Reduce Motion setting.
- Shared fields, buttons, chips, tabs, headings, and back links have clearer accessibility labels, roles, and selected/busy state. Small shared touch targets were enlarged.
- Workout-history chart shows six wider touchable points on compact phones. The planner avoids the keyboard, and primary member/owner content now has a readable maximum width on tablets.

## Remaining findings, prioritized

1. **P1 · Large text and screen-reader pass needed.** `src/member/MemberApp.tsx` and `App.tsx` still use many fixed-size text styles and custom composite rows. At large accessibility text sizes, dense rows, charts, and the role choice may wrap or clip. Test with iOS Dynamic Type and Android font scaling, then replace rigid line heights/row layouts where necessary. Follow with a full VoiceOver/TalkBack traversal. Suggested: `$impeccable adapt`, then `$impeccable polish`.
2. **P1 · Tablet and Android navigation need platform-specific verification.** `src/shell.tsx` uses one hand-built bottom tab bar at all widths. It has accessible labels now, but does not provide iOS navigation-stack edge swipe or an Android expanded-width navigation rail. Verify iPad Split View, Android tablets, and predictive Back before release. Suggested: `$impeccable adapt`, then `$impeccable polish`.
3. **P2 · Owner catalog can grow beyond its current scroll-view structure.** `App.tsx` renders setup choices in a `ScrollView` and caps the initial catalog at 20. That is manageable today, but larger gym inventories need a virtualized, searchable list with clear result count/empty state. Suggested: `$impeccable optimize`, then `$impeccable polish`.
4. **P2 · Some owner forms need keyboard and focus review.** The owner setup and machine-edit flows in `App.tsx` are long forms. Verify that the final fields and save controls remain visible above the keyboard and that focus lands predictably after stage changes. Suggested: `$impeccable harden`, then `$impeccable polish`.
5. **P2 · Hard-coded white-label colors remain.** `src/member/MemberApp.tsx` has literal Vault gold/cream colors alongside shared palette tokens. This works for Vault now, but increases the risk of green/gold leakage when more gyms join. Create semantic gym-theme roles and test both light/dark contrast. Suggested: `$impeccable colorize`, then `$impeccable polish`.

## What is working well

- The black/lime visual system, typography, and spacing are recognizable across member and owner modes.
- Scan has a clear fallback when NFC is unavailable, and machine pages keep log, progress, and learning separate.
- The app already uses safe-area containers, has Android hardware-Back handling, and provides real loading/empty states in major flows.
- The workout planner uses concise input and gym-specific equipment rather than forcing users through a long questionnaire.
